# ErgoCare AI — Test Cases and Results

Every number below was produced by running the scripts in this repository on **26 October 2026** (Windows 11, Python 3.10 venv, Chrome). Anyone can re-run them.

## How to run

All commands run from `ergo_ml_backend` with the backend's virtual environment:

```bat
cd ergo_ml_backend
.venv\Scripts\python scripts\verify_scoring.py          &REM questionnaire scoring rules
.venv\Scripts\python scripts\verify_frontend_parity.py  &REM web app scores = server scores (needs Node)
.venv\Scripts\python scripts\verify_sensor_security.py  &REM wearable security + data integrity
.venv\Scripts\python scripts\verify_pdf_indic.py        &REM PDF renders Hindi + Kannada
.venv\Scripts\python scripts\smoke_wearable.py          &REM starts its own backend, full wearable session over HTTP
.venv\Scripts\python scripts\eval_matcher.py            &REM AI answer-matcher accuracy
.venv\Scripts\python scripts\eval_matcher_500.py        &REM 500-answer matcher test, EN / HI / KN
.venv\Scripts\python scripts\eval_500_participants.py   &REM 500 simulated participants, full scoring (~1 min)

REM These two need the backend running (python -m uvicorn app.main:app --port 8000):
.venv\Scripts\python scripts\verify_wearable.py         &REM + live checks with the real band
.venv\Scripts\python ..\sample_data\run_sample_session.py   &REM end-to-end replay of the sample data (~2.5 min)
```

## 500-sample tests

Both sets are **synthetic** — generated by the team with fixed random seeds, so anyone gets the same numbers. They test that the software behaves correctly on a large, varied input; they are **not** real users and **not** clinical validation. Data: [`sample_data/voice_answers_500.csv`](../sample_data/voice_answers_500.csv) and [`sample_data/participants_500.csv`](../sample_data/participants_500.csv).

### A. AI answer matcher — 500 answers

How it was built: meaning-based phrase lists (never / rarely / sometimes / often / always, yes / no / maybe, 0–5, how strongly, how long) written in 5 forms, placed in everyday sentence frames ("I'd say …", "मुझे लगता है …", "nanage …"), plus English answers that need understanding ("I mostly sit all day"). The expected option comes from the meaning, not from the matcher. Quantity answers (hardest) are deliberately over-weighted: 320 of 500.

| | First run (unseen) | After fixes |
|---|---|---|
| **Overall** | **439 / 500 (87.8%)** | **492 / 500 (98.4%)** |
| Wrong option chosen | 14 (2.8%) | 1 (0.2%) |
| No match — the person taps the option | 47 (9.4%) | 7 (1.4%) |
| English (200) | 90% | 97% |
| Hindi — Devanagari / romanised (75 each) | 89% / 87% | 100% / 97% |
| Kannada — script / romanised (75 each) | 84% / 85% | 100% / 100% |
| Frequency · intensity · yes/no · 0–5 | 98–100% | 100% |
| Quantities (minutes, hours, litres) | 83% | 98% |

What the first run found, and the general fixes made (not answer-by-answer patches):

| Problem found | Example | Fix |
|---|---|---|
| "and a half" not understood → **wrong option** | "an hour and a half" → *1 hour* | "X and a half" → X.5 |
| First frequency word won instead of the most specific → **wrong option** | "once every day" → *Multiple times a day*; "not even once" → *Often* | longest phrase wins; "not even once" = never |
| "almost never" stopped at "never" | → *Never* instead of *Rarely* | "almost" no longer counts as the option word itself |
| "not sure" read as "not confident" | Q23 → *Not confident at all* | "not sure" = *Uncertain* |
| No fractions or numbers above 10 in Hindi/Kannada | "डेढ़ घंटा", "बीस मिनट", "ಒಂದೂವರೆ ಗಂಟೆ", "ಇಪ್ಪತ್ತು ನಿಮಿಷ" → no match | डेढ़/ढाई/आधा/पौने/सवा, ಒಂದೂವರೆ/ಅರ್ಧ, 11–60 added in both scripts and romanised |
| "every hour" not understood | → no match | "every hour" = 1 hour |

**The first-run 87.8% is the honest estimate for phrasing the matcher has never seen**; 98.4% is the same set after fixing what it revealed, so it is no longer unseen. Still missed after fixes: "just one glass" (no unit), "I just walk between classes", "way down, I look down at my laptop", "mujhe lagta hai bees minute", and one wrong option ("I go to the gym every evening" → *Vigorous daily exercise* instead of *Structured activity*). In every case the app shows "Understood as…" and the person confirms or taps another option. All earlier tests (50 / 20 / 30 sets) still give the same results.

### B. 500 simulated participants — full scoring engine

Each participant gets 40 answers from a hidden "true" risk level (posture and workload drawn separately, so answers and body can disagree, plus answer noise); a 60-s calm baseline with their own resting heart rate (62–88 BPM) and skin response; then 4–8 minutes of wearable readings with a **known** share of time slouching and stressed (0–80% each, in 1–3 blocks). 5% have poor sensor contact for the whole session. All go through the server's own functions: `calculate_scores` → `compute_baseline` → `score_session`.

| Check | Result |
|---|---|
| Ran without error | **500 / 500** |
| All scores within 0–100 | **500 / 500** |
| ErgoCare Index = 60% questionnaire + 40% body signals, correct Low / Moderate / High band | **500 / 500** |
| Insights exactly as the documented rules (Hidden stress, Posture blind spot, …) | **500 / 500** |
| Poor sensor contact never produces a stress result (27 participants) | **27 / 27** |
| Questionnaire score rises with the true risk level | Spearman ρ = **0.84** |

Did the wearable detect what was simulated? (473 participants with good contact)

| Detection | All cases | Clear cases (> 5 points from the line) | Measured vs simulated |
|---|---|---|---|
| Slouching ≥ 30% of the time | accuracy 98.1% · sensitivity 96.6% · specificity 100% | **100%** (n = 404, 0 false alarms, 0 misses) | 1.7 points mean difference |
| Stressed ≥ 40% of the time | accuracy 97.3% · sensitivity 100% · specificity 95.5% | **100%** (n = 402, 0 false alarms, 0 misses) | 1.9 points mean difference |

All 22 disagreements (9 slouching, 13 stress) are people within **2.2 points** of a threshold: body signals take a few seconds to rise and settle, so 31.5 % slouching measured as 28.6 %, and 38.6 % stressed measured as a stress score of 47.6 (skin response settles slowly after a stressful stretch, which also explains the 95.5 % specificity). Insights produced across the 500: Posture problem confirmed 169 · Stress confirmed 122 · Posture blind spot 99 · Hidden stress 76 · Calm during the test 39.

**What this proves:** the scoring software is robust and does exactly what its rules say on 500 varied sessions. **What it does not prove:** that the rules match a clinician's judgement, or that real people's signals behave like the simulator's — that needs the planned pilot.

## Not yet tested (honest gaps)

- No clinical validation: scores have not been compared with physiotherapist or doctor assessments.
- Hindi and Kannada test answers were written by the team; they need testing with native speakers and real speech recognition output.
- The browser speech service itself is not under test (it needs internet and varies by browser).
- Both 500-sample tests are synthetic: the 500 answers were written by the team, and the 500 participants' body signals come from the simulator's model of a person, not recordings of real people.
